# 0004. 手写解析器从 PDF/DOCX 提取简历文本

- 状态：已接受
- 日期：2026-09-21

## 背景与问题

简历管理支持上传 txt/md/pdf/docx，需要提取纯文本供填写与建议使用。引第三方解析库（如 pdf.js、mammoth）会带来几十万行依赖，与「无 npm 依赖、无构建」冲突。

## 决策

在 `resume-text.js` 手写最小解析器：DOCX 按 zip 本地文件头逐项解析（含手写 inflate，基于 `DecompressionStream` 的 `deflate`/`deflate-raw`），取 `word/document.xml` 转文本；PDF 用流对象扫描，`FlateDecode` 段解压后抽取字面量文本。`.doc`（旧二进制格式）明确不支持，返回空并提示用户转存。PDF 是启发式提取，复杂排版可能取不全。

## 理由

- 覆盖简历上传的主流格式，代码量可控（单文件百来行），零依赖。
- 解压能力复用浏览器内置 `DecompressionStream`，不手写 inflate 算法本体。
- 启发式的代价可以接受：简历文本只用于本地填写和建议，且 UI 明确支持粘贴正文兜底。

## 影响

- 解析失败的兜底路径是让用户「直接粘贴正文」，新增格式支持前先确认这条兜底仍在。
- 手写二进制解析没有第三方库背书，改动 `unzipEntries`/PDF 扫描逻辑时必须在真实文件上手动验证（可用 `tests/` 下的夹具思路）。
- 不要在这里扩展成通用文档转换器；只服务「拿到可读正文」这一个目的。
