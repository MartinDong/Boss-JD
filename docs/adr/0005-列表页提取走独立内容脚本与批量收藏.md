# 0005. 列表页提取走独立内容脚本与批量收藏

- 状态：已接受
- 日期：2026-09-21

## 背景与问题

原插件只注入 `zhipin.com/job_detail/*` 岗位详情页，用户希望也能在推荐/搜索列表页（`https://www.zhipin.com/web/geek/jobs?…`）直接提取岗位，并在列表展示岗位的基础要求（经验、学历、技能标签）与工作地点。

列表页与详情页 DOM 结构完全不同：详情页是单个岗位的富信息页；列表页是若干张岗位卡片（社区已知结构为 `.job-list-box` 下的 `.job-card-wrapper`），字段以「职位名 / 薪资 / 地点 / 经验学历标签行 / 公司行」的扁平文本块出现，且卡片 DOM 会随版本变动。

## 决策

- 新增独立内容脚本 `list-extract.js`（命名空间 `BossJdList`），只负责列表页卡片解析，挂到 `BossJdList` 命名空间；不把列表逻辑塞进 `extract.js`。
- manifest 增加第二条 `content_scripts`：在 `/web/geek/jobs` 注入 `extract.js, resume-text.js, fill.js, list-extract.js, content.js`，保持与详情页相同的其余脚本。`popup.js` 的兜底注入列表同步。
- 卡片解析用「宽选择器 + 结构兜底」双保险：优先类名选择器（`.job-name`、`.salary`、`.job-area`、`.job-info .tag-list li`、`.company-info .name`、`.info-public` 等），任一选择器失配时回退到对卡片做逐行文本解析（按已知语义行模式识别薪资、地点、经验、学历、公司、招聘者）。
- 收藏走 `background.js` 新增消息 `BJD_LIST`（op `collect` 返回本页全部卡片、op `saveAll` 批量写库、op `saveOne` 写单条），复用 `BossJdDB.saveFavorite`，不在列表页直接访问 IndexedDB（遵守 ADR 0002）。
- 卡片记录带 `source: "list"`，`summary` 字段保存卡片上的原始概要行（地点+经验+学历+标签的拼接），详情字段照常落库，供收藏列表直接展示「基础要求与工作地点」。

## 理由

- 详情页与列表页生命周期、滚动加载、选择器演进节奏不同，独立文件让两边各自演化，互不拖累；ADR 0001 的全局命名空间模式天然支持按 URL 分别注入。
- 纯选择器方案在 BOSS 改版时会整页失配；纯文本解析在正常版式下又不如选择器精确。「选择器优先、文本行兜底」在两类失败模式下都能给出可用结果，符合本项目无构建、可读性优先的取向。
- 批量收藏放后台一次事务化逐条写库（复用现有 `saveFavorite`），UI 侧不引入第二个数据库访问路径。

## 影响

- 新增内容脚本文件时，manifest 的两条 `content_scripts` 与 `popup.js` 兜底注入列表三处都要同步（ADR 0001 的既有约束扩大为三处）。
- 列表页卡片没有职位描述与公司地址等详情页专属字段，落库时留空；coach 建议筛选依赖的 `title/company/location/tags` 均有值，不受影响。
- BOSS 改版仅改 `list-extract.js` 一处；安全验证页判断沿用 `extract.js` 的现有文案约定。
