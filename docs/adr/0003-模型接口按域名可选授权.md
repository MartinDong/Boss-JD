# 0003. LLM 接口地址由用户配置并按域名可选授权

- 状态：已接受
- 日期：2026-09-21

## 背景与问题

求职建议与表单兜底填写需要调用 LLM，但没有官方后端，数据也承诺不出本机之外的第三方收集。需要决定：内置哪个服务商、密钥放哪、如何拿到跨域调用权。

## 决策

不内置任何服务商。用户在 options 页自填 OpenAI 兼容的接口地址、模型名和密钥（存 `chrome.storage.local` 的 `bjd_llm`，仓库中没有任何默认密钥）。保存时用 `chrome.permissions.request` 按该地址的 origin（`origin/*`）申请可选 host 权限；`llm.js` 每次调用前用 `chrome.permissions.contains` 校验，未授权直接报错提示回配置页授权。

manifest 只常驻 `https://www.zhipin.com/job_detail/*` 的 host 权限，其余网站全部走 `optional_host_permissions` 按需申请。

## 理由

- 零内置密钥、零固定第三方域名：权限面最小化，安装时即申请的只有 BOSS 岗位页。
- 用户自选 OpenAI 兼容端点，可以指向本地模型或自有代理，数据流向由用户掌握。
- 每次调用前校验权限，避免「保存过但后来被撤权」后静默失败。

## 影响

- 新增任何出网请求都要走 `llm.js` 的授权校验路径，不允许绕过它直接 `fetch`。
- 模型配置的读写只有 `BossJdLlm.readSettings`/`writeSettings` 一个入口，key 固定 `bjd_llm`。
- 兼容性兜底（如 400 时去掉 `temperature` 重发）只能作为同一端点内的参数降级，不引入第二套协议。
